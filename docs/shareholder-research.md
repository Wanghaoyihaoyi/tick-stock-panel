# 股东与公告联网核验

在策略、自选等页面打开个股详情，展开底部「股东与公告核验」，选择资料截止日后点击「联网核验」。项目调用已经登录的 Codex CLI 的实时 Web Search，通常需要数分钟，无需逐页使用 Computer Use 收集资料。运行期间需保持后端和网络可用。

## 资料与时间口径

覆盖股东户数、十大流通股东、机构持股与新进机构、减持、限售解禁、立案调查与监管公告六项。优先搜索巨潮资讯、沪深北交易所及证监会原文；模型提供摘要、短摘录、公告日期、报告期和来源链接。

截止日按北京时间日终解释。后端排除模型返回的截止日之后的公告，以及官方域名白名单之外的链接。报告期与公告日分开保存，检索时间另外记录。日期和摘要仍属于模型提取，需要打开原文核对；域名校验不等于验证链接内容或公告完整性。

缺少证据明确显示「缺少证据」，不能解释为没有风险。联网报告是按需生成的研究草稿，不直接计分或自动排除候选股。逐项核对原文后，可通过下文的独立复核记录更新筹码候选综合评分；历史回测仍使用技术信号，也不把今天搜索到的资料当作历史时点完整数据。

## 运行与保存

- AI 设置须选择已登录的 Codex CLI，并具备实时搜索权限；其他文本模型配置暂不支持此入口，不会静默退化为凭模型记忆生成。
- 只有检测到 CLI 的真实搜索完成事件且报告格式正确后才保存；调用、搜索或解析失败会显示错误。
- 报告存在项目数据目录下的 `user_data/shareholder_research.json`，通过共享报告存储原子写入，最多保留最近 200 份。
- 同一股票与截止日可以复用当天已检索的报告；「重新联网核验」主动生成新记录。读取历史报告不调用模型。
- 同一股票不并发重复搜索，全局同时最多两项。刷新页面或关闭个股详情不会取消后端已经启动的搜索，可稍后重新打开查看。
- 本功能按点击触发，不自动每天扫描全市场。日线行情同步继续使用原来的行情数据源与盘后管道。

## 二开位置与兼容

前后端使用已实现的 `stock-preview.footer` 插槽和后端扩展路由（L2）。核心 AI 适配器增加可选的联网模式（L3），默认文本生成行为不变。前端请求与查询键沿用公共客户端和缓存。升级上游时重点复核 `ai_provider.py` 的 CLI 参数与 JSONL 事件格式，以及 `api.ts` / `queryKeys.ts` 的新增契约。

接口：`GET /api/disclosure-research/reports?symbol=002297.SZ`；`POST /api/disclosure-research/research`，请求包含 `symbol`、`as_of`、可选 `refresh`，成功返回 `{report: ...}`。所有报告初始为待人工核验。


## 筹码候选综合评分（2026-09-12 更新）

当前 `custom_mtxs8bfe` 已启用 `disclosure_scoring=chip_holder_v1`，页面名称为「筹码峰·股东核验」。技术矩阵依旧负责筛出候选；选择这张策略卡时，评分列读取相同交易日、代码哈希及参数匹配的复核记录。只有股东因子与公告风险覆盖全部齐备才显示最终分和评级；否则显示参考分或区间、待核验状态。其他策略及「全部」视图仍按原技术排序分显示。

综合原始分 = 筹码35 + 趋势25 + 股东25，除以85换算百分制。股东四项分别为户数下降10、十大流通合计占比8、机构占比5、新进入前十机构2。阈值按原 `strategy-v1`：户数下降超过10%得10分、至少5%得7分、其他下降得4分；持股占比增加至少1个百分点得满分；新进入前十不是首次建仓。比例采用当期流通股本的可比口径，不直接累加报告中的总股本百分比。

复核输入独立保存在 `user_data/shareholder_assessments.json`，模型搜索草稿不会自动变为已复核输入。使用 `scripts/update_chip_shareholder_assessments.py` 可从已逐项核对原文的输入包重算技术分项并保存记录；在项目根目录用 backend 的 Python 环境运行。脚本不做自动审批，未来日期或策略变更后需重新核验生成相应记录，不沿用旧日期分数。

本次2026-09-11候选复核：航天彩虹66/85（77.65参考分）、博云新材64/85（75.29参考分）、金百泽59/85（69.41参考分）。三只股东因子已计算，风险覆盖未完整，最终评级均留空。数据明细属于本地研究资料，不提交Git。该功能没有声称复刻原版筹码模型，也不把本次核验变成历史可成交信号；回测和实时监控仍为技术候选信号。
